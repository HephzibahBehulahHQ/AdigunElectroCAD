In continuation of your pursuit of the  goal, upgrade the Adigun Bot
from a prompt-only assistant into a LIVE CO-PILOT that works alongside the user
while they design on the canvas. The Bot should observe what the user is doing
and proactively offer help — not wait to be asked.

THE BEHAVIOR WE WANT

While the user is working on the canvas, the Bot should be live and aware of:
- What components are currently on the canvas.
- What the user just placed, moved, wired, or deleted.
- Whether the current ladder looks incomplete or unsafe.
- Whether the user seems stuck (e.g., placed a switch but no output, wired a
  gate with no input, left a rung unconnected).
- What the user is likely trying to build based on the pattern so far.

And then it should proactively offer, in a calm, non-intrusive way:

1. Suggestions
   - "I see you placed a motor but no start/stop buttons — want me to add them?"
   - "This rung has an AND gate with only one input connected. Should I wire the
     second switch to it?"
   - "You have a lamp but no driver. Want me to add a coil or gate to drive it?"

please note the above is a sample , the Adigun ai must ask or asnwwer or perform a task related to the website and the user purpose 

2. Help offers
   - "Do you want me to complete this for you?"
   - "I can help you finish this — should I build the missing wiring?"
   - "I noticed this may be a start/stop circuit. Want me to finish it?"

3. Questions about the current project
   - "What are you trying to build? I can help faster if I know the goal."
   - "Is this a motor control circuit or a logic demo?"
   - "Should the emergency stop cut power to the whole ladder or just this rung?"

4. Warnings (only when real)
   - "This output has no power source — it will never turn on."
   - "Two outputs are wired to the same coil — this may cause a conflict."
   - "This timer is not connected to anything."
   Never invent warnings. Only warn when the canvas actually has a problem.

5. Live explanations
   - When the user hovers or selects a component, the Bot can explain what it
     does and how it is currently wired.
   - When the user asks "what does this do?", the Bot answers using the real
     canvas state.

HOW IT SHOULD FEEL
- Calm, helpful, never annoying.
- Suggestions appear in a small, dismissible side panel or speech bubble —
  never as a modal that blocks the canvas.
- The user can ignore, accept, or dismiss any suggestion in one click.
- The Bot never modifies the canvas without the user accepting.
- Rate-limited: no more than one proactive suggestion every ~20–30 seconds,
  and none while the user is mid-drag or typing.
- The user can turn the live co-pilot on or off from the Bot panel.

WHAT THE BOT MUST UNDERSTAND
- The Bot must know the canvas state at all times (components, wires, rungs,
  tags, simulation state) through a live subscription, not a snapshot.
- It must distinguish "user is actively editing" from "user is idle" so it
  doesn't interrupt mid-action.
- It must know what is already wired vs. floating, what is powered vs. dead,
  and what is duplicated or conflicting.
- It must know the current project's goal if the user has stated one, so its
  suggestions match that goal.
- It must be able to ask the user questions when the goal is unclear, and use
  the answer to refine its suggestions.

WHAT TO BUILD
1. A live canvas-state subscription that feeds the Bot with every change
   (debounced so it doesn't fire on every pixel move).
2. An "analyzer" that runs on the canvas state and detects:
   - Incomplete patterns (missing inputs, outputs, power, ground).
   - Stuck states (component placed but not wired for >N seconds).
   - Ambiguous goals (no clear input → output chain).
   - Real problems (floating outputs, duplicate coils, unconnected timers).
3. A "suggestion engine" that turns analyzer findings into short, actionable
   offers, each with:
   - A one-line explanation.
   - An "Accept" button (applies the fix, with preview + rollback).
   - A "Dismiss" button.
   - A "Tell me more" button (opens a short explanation).
4. A "question engine" that asks the user about the project goal when the
   canvas is ambiguous, and remembers the answer for the session.
5. A non-blocking side panel or speech bubble UI for suggestions.
6. On/off toggle for the live co-pilot.
7. Rate limiting so it never feels spammy.
8. Tests for:
   - Detects a floating output and suggests the right fix.
   - Detects a missing input on an AND gate and suggests the second switch.
   - Asks about project goal when the canvas is ambiguous.
   - Does not fire suggestions while the user is mid-drag.
   - Accepting a suggestion applies it with rollback on failure.
   - Dismissing a suggestion does not repeat it immediately.
   - Rate limiting is respected.

LOGIN AND SAVING
- Live suggestions work for guests too (they help users learn).
- Accepting a suggestion that saves to local or cloud still requires login.
- The Bot never auto-saves.
