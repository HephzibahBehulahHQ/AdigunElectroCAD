# Current-driven thermal overload — deployment verified

PR #79 is merged as `d8d28e6`; Pages deployment run `41614492416` succeeded. The thermal primitive, nominal feeder-current tracing, wired trip events and live readings are deployed. Production interactive verification remains pending; M04a stays open until that passes.

## Model contract

The educational model retains normalized heat `h`; `h = 1` is the trip threshold. With a constant RMS current, the steady thermal target is `q = (I / settingA / overloadFactor)^2`. The exact interval update is `h(t + dt) = q + (h(t) - q) exp(-dt / tau)`. Heating uses `heatingTimeSeconds`; zero-current cooling uses `coolingTimeSeconds`. A factor of one permits rated current indefinitely without crossing the asymptote. A trip latches until a fresh reset edge is requested with zero current and heat at or below `resetLevel`. A held rejected reset does not become an automatic reset while cooling. Reset retains heat.

`secondsUntilThermalTrip` returns the analytic event time. The circuit integration stops at that event, opens 95–96, settles the wired coils and recalculates current for the remaining interval. Other component clocks retain their existing scan-based behavior; this is not a general circuit-wide event solver. The primitive deliberately does not assume a trip breaks the power path: an overload relay cannot interrupt current when its auxiliary contact is bypassed or not wired into the contactor coil.

Parameters are explicit; no manufacturer calibration or IEC trip-class conformity is claimed. This is a single retained thermal state, without separate rotor/stator heating, ambient compensation, phase-unbalance heating, inrush or electromagnetic motor dynamics. ABB's [motor thermal protection operation principle](https://techdoc.relays.protection-control.abb/r/REX615-Technical-Manual/PCL1/en-US/MPTTR-Operation-principle) describes current-squared heating and condition-dependent time constants; it motivates this simplified model but does not validate these application parameters or certify this implementation.

## Evidence and remaining integration

Nine focused tests cover analytic cold/hot trip timing, the rated-current asymptote across repeated intervals, exponential cooling, latched reset rejection, a fresh cool reset, continuing heating when current persists after trip, coarse/fine constant-current agreement and invalid input rejection. The original state is not mutated.

The feeder tracer follows the existing conducting graph and assigns each energized nominal motor's configured RMS current only to relay poles whose removal disconnects that phase from its source. It sums distinct downstream loads per pole and uses the maximum pole current. Parallel and bypassed paths return an explicit current-division error; no partial sum is presented as valid. Forward and reverse wired circuits both produce 14.1 A per pole in the checked example. An open breaker or incomplete motor phase supply gives zero current under the existing balanced nominal motor model. This is not an impedance-network solve or a phase-loss heating model; other load families, drive-dependent currents and transient motor currents remain outside this checkpoint.

## Operation and acceptance

Load **Current-driven thermal overload** from the project library. Press/release S1 using Live Pressed, select F1 and run the simulation clock. Its 14.1 A nominal load exceeds the deliberately low 7.05 A relay setting. With overload factor 1 and heating constant 10 s, the cold trip occurs after about 2.88 s. F1 opens 95–96; the holding coil drops and motor current becomes zero. The power poles themselves remain conductive, as a thermal relay does not interrupt its own feeder.

Pause preserves retained heat. Live Reset is rejected above 50% heat or with nonzero current. Running with zero current cools with a 20 s constant. Holding a rejected reset while cooling does not reset the latch: release it and issue a fresh reset below 50%. Heat is retained and the motor remains stopped until another START. The library sequence demonstrates a faster subsequent warm trip. Stop restores the saved design and clears runtime heat; it is a simulator reset, not a physical cooling action.

Thermal Enabled is explicit and defaults off on legacy relay placements, preserving their manual-trip behavior. The new example enables it. Time constants and overload factor define the model; legacy imported tripClass/resetMode properties do not calibrate it. New relay placements no longer expose those unused defaults. Invalid thermal parameters, ambiguous current paths and unsupported connected load/converter models produce a fault and inhibit the wired coil. After interruption, valid zero-current cooling continues even with a retained fault; a fresh cool reset clears the fault latch. Bypassing 95–96 defeats interruption and continued current continues heating.

Tests cover constant-current analytic timing, asymptotic rated load, coarse/fine intervals across trip and cooling, cold/hot reset, retained heat, control-contact bypass, invalid settings/current paths, repaired-fault recovery, graph paths, and the recorded project sequence. Local browser acceptance observed 14.10 A before Run, automatic trip with zero current, hot reset rejection at 62.1% heat, a held reset remaining latched below 50%, and a fresh reset retaining 8.3% heat with M1 still STANDBY. Undo/reload restored the original two-sheet local project without cloud writes.
