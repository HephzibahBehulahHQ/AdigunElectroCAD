text to make ai caht box float 

 change the Adigun Bot chat Templates 
from a fixed modal into a floating, draggable, resizable window that sits on top
of the workspace.

WHY
Users need to keep working on the canvas while the Bot is open. A fixed modal
blocks the workspace. A floating window can be moved anywhere, minimized when
not needed, and restored when wanted, so the user can design and chat at the
same time.

WHAT TO BUILD

1. Floating window container
   - The Bot opens as a floating panel when the user clicks the AI icon.
   - It is NOT a full-screen modal. It does not block the canvas behind it.
   - It sits above the canvas (higher z-index) but the canvas remains interactive.
   - The user can click the canvas while the Bot is open.

2. Drag to move
   - Click and drag the Bot's title bar (header) to move the whole window
     anywhere inside the browser viewport.
   - Constrain the window so it cannot be dragged off-screen (at least the
     title bar must remain visible so the user can always grab it back).
   - Remember the last position (per user, per project if possible) so the
     next time it opens, it opens where the user left it.

3. Resize
   - The window has a resize handle (bottom-right corner is standard).
   - The user can drag the handle to make the window larger or smaller.
   - Set sensible min and max sizes (e.g., min 320×400, max 900×800, or a
     fraction of the viewport).
   - Remember the last size (per user) so it reopens at the same size.

4. Window controls (top-right of the header)
   - Minimize: collapses the window to just the title bar (or a small pill),
     so it stays out of the way but is still visible.
   - Maximize: expands the window to fill most of the viewport (but still not
     full-screen modal — keep the canvas usable around the edges).
   - Restore (when maximized): goes back to the previous size and position.
   - Close: hides the window entirely. Clicking the AI icon reopens it.
   - All controls must have tooltips and clear icons (dash, square/double-square,
     X).

5. AI icon behavior
   - The AI icon lives in a fixed position in the UI (e.g., bottom-right corner
     or in the top menu bar — match the existing pattern).
   - Clicking the icon:
     - If the window is closed → opens it at the last remembered position/size.
     - If the window is open → brings it to the front (or toggles minimize, if
       that matches the platform convention).
   - The icon shows a small dot or badge when the Bot has a new message or a
     pending suggestion.

6. State persistence
   - Remember per user: window position, window size, minimized state,
     maximized state.
   - On page reload, the window should reopen exactly as the user left it
     (or stay closed if they closed it).
   - Use localStorage for guests, and the user's Supabase account for logged-in
     users (so the layout follows them across devices if you want that later —
     at minimum, localStorage is fine for now).

7. Interaction with the live co-pilot
   - When the Bot suggests something (proactive live suggestions), the window
     must NOT auto-open and steal focus.
   - Instead, show a small badge on the AI icon and a toast/notification.
   - The user opens the window when they want to see it.

8. Accessibility
   - Keyboard: Escape closes (or minimizes) the window; Tab cycles through
     controls; Enter sends a message.
   - Focus management: when the window opens, focus the input field. When it
     closes, return focus to the AI icon.
   - Screen readers: proper ARIA roles (dialog or complementary), labelled
     controls.

9. Mobile / touch
   - On small screens, the floating window can become full-screen when opened,
     with a clear close button.
   - Drag and resize work with touch gestures too.

10. Tests
   - Drag the window, release, reload the page → window reopens in the same
     position.
   - Resize the window, reload → same size.
   - Minimize → canvas is fully usable → restore → window returns to previous
     state.
   - Maximize → restore → returns to previous size and position.
   - Close → AI icon shows → click → window reopens at last position.
   - Canvas is interactive while the window is open (click a component behind
     the window works).
   - Live suggestion arrives → window does NOT auto-open → badge appears.
   - Keyboard-only: open, navigate, minimize, close, reopen.
   - Mobile viewport: opens full-screen with a working close button.

DESIGN NOTES
- Keep the visual style consistent with the existing app (same colors, radius,
  shadow, font).
- The window should feel lightweight — a floating panel, not a heavy modal.
- The header shows: Bot title, status (Hosted AI available / Offline), and the
  window controls.
- The body is the chat transcript and input.
- The footer (optional) shows the current project context and a "Clear chat"
  button.

DELIVERABLES
1. The floating Bot window implemented with drag, resize, minimize, maximize,
   restore, close, and reopen.
2. State persistence (position, size, minimized/maximized) via localStorage for
   guests and account storage for logged-in users.
3. Badge behavior on the AI icon for unread messages / pending suggestions.
4. Accessibility (keyboard + ARIA) and mobile behavior.
5. Tests covering all the scenarios above.
6. An update to docs/HELP.md: "Using the Bot window" — how to move it, resize
   it, minimize/maximize/close, and how to reopen it. Add it to the Table of
   Contents.
